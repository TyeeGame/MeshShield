# USB-only protocol

The Argon announces JSON summaries with `ingress: usb_virtual`. The backend waits for that marker and a fresh session before sending traffic. All lines use newline termination and USB baud setting 115200. Firmware reads at most 128 bytes per loop into a 256-byte command buffer, and uses six bounded outbound frames. Oversized input is discarded through newline.

Traffic envelope: `T,<decimal gateway session>,<slot 1 or 2>,<36 hexadecimal packet digits>\n`. The 18-byte packet is version(1), type(1), sequence(4 little endian), endpoint uptime(4), sensor(2 signed little endian), overflow(4), CRC16(2 little endian). CRC-16/CCITT-FALSE uses initial 0xffff, polynomial 0x1021, no final xor; `123456789` yields 0x29b1. Host generates the packet; Argon validates CRC, version, and type and applies policy. Type 0 is empty, 1 telemetry, others rejected. Invalid traffic envelopes/stale sessions produce malformed_command errors and do not target a device policy. Accepted envelopes with bad packet CRC/version/type enter policy accounting.

Control remains flat JSON: session, id, op (quarantine/release/state), node, duration_ms. Management IDs are separate from traffic packet sequences. Duplicate commands do not extend containment. Host owns both virtual identities and management; no authentication boundary is claimed.

Argon events retain v/session/seq/type and the prior summary, telemetry, incident, ack, error fields. Summary reports duration_ms, uptime_ms, log_drops, last_command_id, and two node rows. Each row has received/allowed/blocked, quarantine_ms, contaminated, seen_age_ms/message_age_ms, and reason counts. Legacy transport/empty/queue_overflow fields remain compatible; no I2C polling occurs. Counts are interval deltas; displayed totals omit lost intervals. Raw telemetry events are sampled at most once per node per second; counters cover all evaluated packets.

Backend mode selector: POST /api/traffic/mode with {"mode":"NORMAL"}, UNKNOWN_TYPE, FLOOD, or ANOMALY. The old /api/simulation/mode route is retained as an alias. Hardware mode changes laptop-generated traffic, not the Argon's policy. Fully simulated mode models both endpoints and gateway in software. Hardware filtering decisions come from the board only.
# Real-message extension

Message-capable firmware adds integer `messages: 1` to its summary. After a fresh summary, the single USB owner provisions a random 16-byte sender code with `K,<session>,<configuration id>,<32 hex code digits>\n`. The firmware responds with a sequenced `message_ready` event carrying that configuration ID. Reconnect requires a new summary and readiness acknowledgment. This provisioning channel is trusted USB management and is not exposed as a LAN endpoint.

`M,<session>,<message id>,<32 hex code digits>,<2–320 hex text digits>\n` carries 1–160 UTF-8 bytes. The firmware strictly parses the bounded hex envelope, compares the bearer code and applies independent message policies to approved (slot 1) or unauthorized (slot 2) traffic. The original 18-byte virtual packet format and its CRC/version checks are unchanged; the new message envelope relies on USB transport integrity and does not add a cryptographic message signature. The trusted host handles UTF-8 validation and text rendering.

`message_decision` events contain `id`, `slot`, `reason` (`allowed`, `unauthorized`, `rate_limit`, `quarantine`) and `quarantine_ms`, plus the normal version/session/event-sequence envelope. IDs increase within a provisioning cycle; duplicate/older message IDs are ignored, and messages are not retried. The backend accepts a decision only for a sent pending message in the current session, delivers at most once, and drops pending text after a five-second timeout or disconnect. Missing decisions never deliver text. Original JSON quarantine/release/state commands retain their separate IDs and acknowledgments.
